## <a id="features"></a>✨ Возможности

`agy-manager` объединяет в себе два ключевых инструмента для удобной разработки в экосистеме Antigravity:

- 🔓 **Обход региональных ограничений:** Отключение локальных заглушек доступности ("not available in your location") во всех ключевых компонентах (CLI, Manager, IDE и расширение для IDE).
- 👥 **Менеджер аккаунтов:** Безопасное сохранение и быстрое переключение между несколькими профилями авторизации без необходимости повторного входа через браузер.
- 🎨 **Интерактивный TUI:** Удобное консольное меню для управления патчами и аккаунтами на базе библиотек `rich` и `questionary`.
- ⚡ **Ядро без зависимостей:** Все основные консольные команды работают на стандартной библиотеке Python без необходимости установки сторонних пакетов.
- 🛡️ **Безопасность и откат:** Патчер ищет ровно одну исходную или уже изменённую сигнатуру только в исполняемых секциях PE/ELF/Mach-O, проверяет резервную копию и результат каждой записи и автоматически откатывается при ошибке. Оригинальные файлы сохраняются как `*.agybak`; в macOS состояние подписи `.app` дополнительно сохраняется как соседний каталог `*.app.agysignbak`.
- ⚙️ **Умный автопоиск:** Автоматическое сканирование реестра Windows, системного PATH, переменных окружения и путей Scoop, стандартных путей установки в Linux (`/opt`, `~/.local/share` и др.), а также `.app`-бандлов в macOS (`/Applications`, `~/Applications`) для динамического обнаружения установленных приложений.
- 🧬 **Устойчивость к обновлениям и архитектурам:** Поиск уникальных сигнатур инструкций через регулярные выражения вместо привязки к статическим смещениям, плюс отдельные сигнатуры под каждую архитектуру (x86-64 и aarch64) — один и тот же патч работает и на Intel-, и на ARM-сборках.

## <a id="quick-start"></a>🚀 Быстрый старт

### 1. Склонируйте репозиторий и перейдите в каталог

```bash
git clone https://github.com/QNIX-Dev/eligibility-antigravity-patcher.git
cd eligibility-antigravity-patcher
```

### 2. Выберите режим работы

#### Вариант А: Интерактивный TUI (рекомендуется)

Запуск полноценного интерактивного интерфейса с таблицей статусов для управления как патчами, так и аккаунтами:

1. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```
2. **Запустите agy-manager:**
   ```bash
   python manager.py
   ```

*(Интерфейс поддерживает навигацию стрелочками, выбор пробелом и подтверждение по Enter).*

---

#### Вариант Б: Консольный CLI (без зависимостей)

Работает полностью на стандартной библиотеке Python (установка сторонних пакетов не требуется). Позволяет автоматизировать действия и управлять окружением напрямую из терминала.

| Команда | Описание |
| :--- | :--- |
| `python manager.py status` | Проверить статус патча для всех приложений. |
| `python manager.py patch` | Пропатчить все найденные приложения. |
| `python manager.py restore` | Восстановить все приложения из оригинальных бэкапов. |
| `python manager.py patch <cli\|manager\|ide\|extension>` | Пропатчить только выбранные приложения. |
| `python manager.py accounts <cli-manager\|ide> <действие> [имя1] [имя2]` | Управление сохраненными профилями авторизации (подробнее см. ниже). |

> [!TIP]
> Если ваше приложение установлено в нестандартную директорию, вы можете вручную указать путь к нему:
> ```bash
> python manager.py --path-cli "D:\CustomTools\agy.exe" patch cli
> # Либо для бэкенда расширения:
> python manager.py --path-extension "D:\CustomTools\agy.exe" patch extension
> ```

> [!NOTE]
> **Особенности работы на macOS (подпись кода и Gatekeeper):**
> - **Автоматическая ad-hoc подпись:** Патчер автоматически переподписывает изменённые Mach-O бинарники (`agy`, `language_server`) и внешний `.app`-бандл через `codesign`, а также снимает атрибут `com.apple.quarantine`. Исходное состояние сохраняется в `*.app.agysignbak` для отката при `restore`.
> - **Electron и Library Validation:** Если запуск приложения блокируется из-за проверки библиотек Electron (ad-hoc подпись не имеет Team ID), запустите патч с флагом исключения:
>   ```bash
>   python3 manager.py --macos-disable-library-validation patch ide
>   ```
>   Флаг безопасно добавляет исключение `disable-library-validation=true` в entitlements основного исполняемого файла выбранного `.app`. Подробнее см. в [деталях реализации](#details).

## <a id="bypass"></a>🔓 Патчинг региональных ограничений

Патчер нейтрализует локальные проверки доступности и переводит клиенты в соответствующие успешные ветки выполнения.

> [!NOTE]
> Изменения затрагивают только локальную логику клиентов. Этот инструмент **не** создаёт серверные права, не обходит серверную авторизацию и не открывает доступ к платным функциям: итоговая доступность моделей и функций по-прежнему определяется ответами сервера.

### Поддерживаемые приложения

| Идентификатор | Приложение | Метод патчинга | Маркер поиска |
| :---: | :--- | :--- | :--- |
| **`cli`** | **Antigravity CLI** (`agy` / `agy.exe`) | Бинарный патч `agy` / `agy.exe`, нейтрализующий локальный гейт `hasValidAuth` и выбирающий ветку `eligible`. | `agy` / `agy.exe` |
| **`manager`** | **Antigravity Manager** (Electron) | Бинарный патч Go-бэкенда `language_server` / `language_server.exe`, нейтрализующий гейт `hasValidAuth` и выбирающий успешную ветку. | `resources/bin/language_server` / `resources/bin/language_server.exe` |
| **`ide`** | **Antigravity IDE** (VS Code) | Патч минифицированного `main.js`, нейтрализующий локальный auth-гейт и выбирающий укороченную ветку аутентификации. | `resources/app/out/main.js` |
| **`extension`** | **Antigravity Extension** (расширение) | Бинарный патч Go-бэкенда `agy` (`--hub`), нейтрализующий гейт `hasValidAuth` и выбирающий успешную ветку. | `.gemini/bin/agy` / `.gemini/bin/agy.exe` |

> [!NOTE]
> **Поддержка платформ:** Патчи `cli`, `manager`, `ide` и `extension` поддерживают Windows, Linux и macOS. Патч `cli` содержит отдельные x64- и arm64-сигнатуры машинного кода и автоматически выбирает нужную по архитектуре исполняемого файла. Патч `manager` устроен так же: x64-сигнатура покрывает Windows (в том числе Windows-on-ARM, где бэкенд поставляется в x64-версии и работает через эмуляцию), Linux x64 и Intel macOS, а отдельная arm64-сигнатура — Linux arm64 и macOS на Apple Silicon. Патч `ide` изменяет JavaScript и поэтому использует одну архитектурно-независимую сигнатуру на всех платформах. Патч `extension` использует проверенную x64-сигнатуру бэкенда (ARM64 намеренно исключён до проверки сигнатуры в реальных сборках).
>
> В Linux автопоиск сканирует стандартные префиксы установки (`/opt`, `/usr/share`, `/usr/lib`, `~/.local/share`, `~/.local/bin`, каталог лаунчера `antigravity` и `antigravity-ide` из `PATH`). В macOS сканируются `.app`-бандлы в `/Applications` и `~/Applications` (бинарники лежат внутри `Contents/Resources/`); после патча подпись обновляется в порядке «изнутри наружу», а общий bundle подписывается только после всех выбранных targets. Для `extension` автопоиск сканирует каталог `~/.gemini/bin/` независимо от системного `PATH`. Для нестандартных путей укажите их вручную с помощью флагов командной строки (например, `--path-cli` или `--path-extension`). Перед патчем закройте приложения, чтобы избежать блокировок файлов. Управление аккаунтами (`accounts`) на данный момент поддерживается только в Windows.

## <a id="accounts"></a>👥 Менеджер профилей авторизации

Позволяет сохранять текущую сессию авторизации Antigravity под уникальным именем (профилем) и переключаться между ними в офлайне без повторного входа в браузере. 

### Области управления
Управление сессиями разделено на две независимые области:
1. **CLI + Manager** (используют общий токен доступа в Windows Credential Manager).
2. **IDE** (использует собственные ключи авторизации в SQLite базе данных `state.vscdb` внутри VS Code).

Это разделение позволяет независимо переключать профили для разных инструментов и избегает конфликтов блокировки файлов.

### Использование в интерактивном меню:
1. Выберите пункт **Manage accounts** в главном меню `python manager.py`.
2. Выберите целевую область: **CLI + Manager** или **IDE**.
3. Доступны операции сохранения текущей сессии, переключения на сохраненный профиль, удаления профиля или выхода.

### Использование в командной строке:
Формат команды: `python manager.py accounts <cli-manager|ide> <действие> [имя]`

| Действие | Пример команды | Описание |
| :--- | :--- | :--- |
| `list` (или `ls`) | `python manager.py accounts cli-manager list` | Список сохраненных профилей для выбранной области с отметкой активного. |
| `save <имя>` | `python manager.py accounts cli-manager save work` | Сохранить текущую активную сессию под указанным именем. |
| `use <имя>` (или `switch`) | `python manager.py accounts cli-manager use personal` | Переключиться на сохраненный профиль. |
| `logout` | `python manager.py accounts cli-manager logout` | Выйти из текущей сессии локально (чтобы войти в другой аккаунт). |
| `rename <старое> <новое>` (или `mv`) | `python manager.py accounts cli-manager rename work personal` | Переименовать сохраненный профиль. |
| `rm <имя>` | `python manager.py accounts cli-manager rm work` | Удалить сохраненный профиль. |
| `current` (или `who`) | `python manager.py accounts cli-manager current` | Показать имя текущего активного профиля. |

## <a id="details"></a>🔍 Детали реализации (под капотом)

<details>
<summary>🛠️ <b>Патч CLI (`agy.exe` Go-бинарник)</b></summary>

CLI проверяет при запуске поле `hasValidAuth` (байт по смещению `+8`) из AuthResult, пришедшего с сервера. Результат определяет выбор ветки `eligible` или локального экрана «Eligibility Check».

1. **Сборки x64:** Патчер ищет уникальную сигнатуру проверки гейта: `test rax,rax` → `je` (eligible) → `cmp byte ptr [rax+8],0` → `jne` (eligible) → `call failure_builder` → сохранение `rax`, `rbx` и `rcx` в `[rsp+0xd8]`, `[rsp+0xe0]` и `[rsp+0xe8]`. Сигнатура соответствует актуальной CLI 1.2.16 и строго фиксирует эти инструкции; прежние x64-варианты не сохраняются.
2. При нулевом `hasValidAuth` выполнение без патча проваливается дальше и печатает ошибку. Патч заменяет `cmp byte ptr [rax+8],0` на `test rax,rax` (+`NOP`): так как `rax` здесь гарантированно не равен нулю, переход `jne` всегда уводит выполнение в ветку «eligible».
3. В результате локальный гейт всегда выбирает ветку `eligible` как при первом входе, так и при последующих запусках CLI; серверный ответ и глобальная конфигурация продукта не изменяются.
4. **Сборки arm64** (Windows, Linux и macOS) содержат внешнюю проверку: `cbnz x1,error` → `cbz x0,eligible` → `ldrb w2,[x0,#8]` → `tbnz w2,#0,eligible` → `bl failure_builder` → `stp x0,x1,[sp,#0xe0]` → `stp x2,x3,[sp,#0xf0]` → `stp x4,x5,[sp,#0x100]` → `stp x6,x7,[sp,#0x110]`. Сигнатура проверена на CLI 1.2.16 для macOS и Linux ARM64: байты гейта совпадают в обеих сборках. Патч заменяет загрузку флага на `mov w2,#1`, поэтому существующий `tbnz` всегда выбирает ветку «eligible». Класс `MultiGate` автоматически выбирает x64- или arm64-сигнатуру; прежние ARM64-варианты не сохраняются.
</details>

<details>
<summary>📦 <b>Патч Manager (`language_server.exe` Go-бэкенд)</b></summary>

Менеджер общается с локальным Go-бэкендом `language_server.exe` по протоколу connect-rpc. Вердикт `hasValidAuth` (байт по смещению `+8` в AuthResult) определяется в единственном корневом месте — функции `authclient.(*PersonalAuthValidator).Validate`.

1. **Сборки x64:** Патчер ищет в валидаторе уникальную сигнатуру гейта: `cmp byte ptr [rax+8],0` → `je` (пропускает успешную ветку) → `mov rdx,[rsp+0x70]` → `mov [rax+0x60],rdx`. Инструкции контекста фиксированы; изменяться может только смещение перехода.
   Эта же последовательность инструкций проверена в бэкенде agy 1.3.0 (`--hub`) для Windows x64 и используется таргетом `extension` без дублирования сигнатур.
2. Проверка вместе с переходом перезаписывается на `mov byte ptr [rax+8],1` + `NOP`: флаг принудительно выставляется в `true`, а условный переход устраняется, поэтому выполнение продолжается по успешной ветке.
3. Результат этого валидатора возвращает `GetAuthStatus` и используется функцией логина, поэтому обе точки получают один и тот же принудительно успешный вердикт как при первом входе, так и при последующих перезапусках.
4. **Сборки arm64** (Linux arm64, macOS на Apple Silicon) содержат тот же гейт в коде AArch64: `ldrb w3,[x0,#8]` → `tbz w3,#0,skip` → `ldp x3,x4,[sp,#0x80]` → `stp x3,x4,[x0,#0x60]`. Патч переписывает `ldrb;tbz` в `mov w3,#1 ; strb w3,[x0,#8]` — выставляет флаг в `true`, устраняет условный переход и продолжает выполнение по успешной ветке. Сигнатура фиксирует инструкции актуального контекста и допускает только изменение смещения перехода. Класс `MultiGate` автоматически выбирает x64- или arm64-сигнатуру.
</details>

<details>
<summary>🧩 <b>Патч Extension (`agy --hub` Go-бэкенд)</b></summary>

Расширение Google Antigravity запускает загруженный бинарник `agy` с флагом `--hub` и обслуживает интерфейс через локальный HTTP-сервер. Веб-интерфейс вызывает connect-rpc методы `Login` и `GetAuthStatus` language server, проверяет `authResult.hasValidAuth` и при отказе отображает экран недоступности аккаунта.

1. **Сборки x64:** Патчер находит в валидаторе `authclient.(*PersonalAuthValidator).Validate` проверенную сигнатуру гейта: `cmp byte ptr [rax+8],0` → `je` → `mov rdx,[rsp+0x70]` → `mov [rax+0x60],rdx`. Окружающие инструкции контекста сохраняются без изменений.
2. Проверка и условный переход перезаписываются на `mov byte ptr [rax+8],1` + `NOP` + `NOP`: флаг принудительно выставляется в `true`, а выполнение направляется по успешной ветке.
3. В результате методы `Login` и `GetAuthStatus` возвращают положительный вердикт напрямую в интерфейс хаба независимо от терминального гейта обычного CLI.
4. **Архитектурная поддержка:** Таргет определяет архитектуру бинарника и поддерживает x64-сборки. Поддержка ARM64 для бэкенда расширения намеренно отключена до подтверждения соответствующей сигнатуры в реальных сборках.
</details>

<details>
<summary>💻 <b>Патч IDE (`main.js` VS Code)</b></summary>

1. Патчер находит файл `resources/app/out/main.js` и с помощью регулярного выражения ищет минифицированный шаблон авторизации: `resetIsTierGCPTos\(\),this\.[A-Za-z_\$0-9]+\.isGoogleInternal`.
2. Заменяет его на `resetIsTierGCPTos(),true`, поэтому только эта проверка всегда выбирает внутреннюю укороченную ветку аутентификации; глобальный `isGoogleInternal` остаётся выключенным.
3. Очищает кэши байт-кода VS Code (`CachedData` и `Code Cache/js`) для моментального применения изменений.
</details>

<details>
<summary>👥 <b>Менеджер аккаунтов (хранение и переключение сессий)</b></summary>

Механизм переключения аккаунтов работает полностью локально и офлайн, не обращаясь к серверам авторизации (штатный выход из приложения инвалидирует токен на стороне сервера).

1. **Разделение хранилищ:** Токены CLI/Manager берутся из Windows Credential Manager (`gemini:antigravity`). Токены IDE вычитываются из SQLite базы данных VS Code `state.vscdb` (ключи `antigravityUnifiedStateSync.*`).
2. **Безопасное хранение:** При сохранении профиля данные шифруются/кодируются и записываются обратно в Credential Manager под уникальным именем с префиксом `agy-manager:account:cli-manager:<name>` или `agy-manager:account:ide:<name>`.
3. **Обход лимитов размера:** generic-записи в Credential Manager ограничены размером в 2560 байт, в то время как JSON-сессия IDE может превышать 8 КБ. Профили IDE автоматически шардируются на части по 2000 байт и сохраняются в виде пронумерованных записей (`.../<index>`).
</details>

<details>
<summary>🍎 <b>Подпись кода и Library Validation в macOS</b></summary>

Патчер полностью автоматизирует цепочку создания подписи и разрешений для запуска изменённых приложений на macOS:

1. **Порядок подписи:** Сначала применяются и верифицируются бинарные патчи, затем создаётся ad-hoc подпись для каждого изменённого Mach-O (`agy` и `language_server`), и в последнюю очередь подписывается внешний `.app`-бандл (порядок «изнутри наружу»). Каждая операция верифицируется через `codesign --verify`; при ошибке выполняется откат.
2. **Снятие карантина:** После успешной подписи патчер рекурсивно удаляет атрибут `com.apple.quarantine` с пропатченного `.app` (через API Python либо встроенную утилиту `/usr/bin/xattr`), предотвращая блокировку локально изменённого кода со стороны Gatekeeper.
3. **Electron и Library Validation:** До записи проверяются флаги подписи и entitlements. При активной Library Validation ad-hoc подпись теряет Team ID и конфликтует с Electron Framework. Флаг `--macos-disable-library-validation` добавляет исключение `com.apple.security.cs.disable-library-validation=true` в entitlements основного executable, сохраняя Hardened Runtime и все остальные разрешения.
4. **Резервные копии и откат:** Исходные метаданные подписи и entitlements сохраняются в соседнем каталоге `*.app.agysignbak`. Команда `restore` полностью восстанавливает исходную подпись бандла после отката последнего пропатченного таргета.
</details>

## <a id="warnings"></a>⚠️ Важные примечания

- **Совместимость версий:** Работоспособность патчера гарантируется только на **актуальных** версиях приложений. Он завязан на бинарные сигнатуры конкретных сборок, поэтому на устаревших версиях может не находить нужные инструкции и просто ничего не делать — статус отобразится как `unknown`, а файл останется нетронутым (безопасный отказ). В этом случае обновите приложение до последней версии.
- **Сброс при обновлениях:** При обновлении приложений пропатченные файлы будут перезаписаны оригинальными. Достаточно повторно запустить `python manager.py patch`.
- **Блокировка файлов и процессов:** Перед патчингом или переключением аккаунтов обязательно закройте все целевые приложения соответствующей области (CLI, Manager, IDE или редактор с установленным расширением). В противном случае операционная система заблокирует доступ к файлам, либо запущенное приложение перезапишет восстановленные токены из своего кэша в оперативной памяти.
- **Безопасность токенов:** Все ваши учетные данные (как текущие активные, так и сохраненные профили) остаются строго на вашей машине. Они хранятся в защищенном системном хранилище Windows Credential Manager и SQLite базе данных VS Code и никогда не передаются сторонним серверам.
- **Условия использования:** Изменение проприетарного кода приложений может нарушать условия использования (ToS). Данный проект создан исключительно в образовательных целях — используйте его под свою ответственность.
